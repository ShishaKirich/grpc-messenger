# Безопасность SecureGate

В этом документе описано, от каких угроз защищено приложение, как именно и какие ограничения остаются. Ссылки ведут на код, в котором реализована каждая мера.

## Модель угроз

| Угроза | Защита | Где в коде |
|---|---|---|
| Утечка базы данных | Пароли хранятся как хеши Argon2id (19 МБ, 2 прохода). Коды хранятся как HMAC-SHA256 с секретным ключом. Токены сеансов и устройств хранятся как SHA-256. По содержимому базы нельзя войти ни в один аккаунт. | `app/security.py`, `app/sessions.py` |
| Подбор пароля | После 5 неудачных попыток за 15 минут вход для этого email блокируется. Требования к паролю: длина от 10 символов, оценка zxcvbn не ниже 3, пароль не должен встречаться в утечках. | `app/main.py` (`login`), `app/passwords.py` |
| Слабые и утёкшие пароли | zxcvbn учитывает словари, шаблоны клавиатуры, имя и email пользователя. Пароль проверяется по базе Have I Been Pwned методом k-анонимности: наружу уходят только первые 5 символов SHA-1, ответ дополняется фиктивными строками (`Add-Padding`). | `app/passwords.py` |
| Перехват или подбор кода | Код состоит из 6 цифр, генерируется через `secrets` и живёт 5 минут. После 5 неверных попыток он сгорает, а при запросе нового кода старый перестаёт действовать. Попытка засчитывается до сравнения, сравнение выполняется за постоянное время. Лимит: не больше 10 кодов на пользователя в час, то есть не больше 50 попыток в час на миллион вариантов. | `app/otp.py` |
| Взлом почтового ящика | Можно подключить приложение-аутентификатор (TOTP, RFC 6238). Тогда второй фактор не зависит от почты, и восстановление пароля по email тоже требует кода из приложения. | `app/totp.py`, `app/main.py` (`reset`, `verify_totp_login`) |
| Утечка секрета TOTP из базы | Секрет хранится зашифрованным (Fernet: AES-128-CBC + HMAC-SHA256), ключ выводится из `SECRET_KEY`, которого в базе нет. QR-код строится на сервере (segno) и встраивается в страницу как `data:`-URI, поэтому секрет не уходит во внешние сервисы генерации QR. | `app/totp.py` |
| Повтор перехваченного кода из приложения | Сохраняется номер последнего принятого 30-секундного интервала, и принимаются только более новые (атомарный `UPDATE ... WHERE totp_last_step < ?`). Допускается расхождение часов ±30 секунд. | `app/totp.py` (`verify_and_consume`) |
| Перебор кода из приложения | Неверные коды считаются вместе с неверными паролями: после 5 ошибок за 15 минут вход блокируется. | `app/main.py` (`verify_totp_login`) |
| Потеря телефона | 10 одноразовых резервных кодов (около 40 бит каждый), в базе хранится HMAC. Использование кода сопровождается письмом с числом оставшихся кодов. Новые коды выдаются только по коду из приложения. | `app/totp.py` |
| Отключение 2FA злоумышленником | Нужны и текущий пароль, и код из приложения (или резервный). Владельцу приходит письмо. | `app/main.py` (`totp_disable`) |
| Повторное использование кода (race condition) | Код помечается использованным атомарным `UPDATE ... WHERE used = 0`. Из двух одновременных запросов пройдёт только один. | `app/otp.py` (`check_code`) |
| Перебор аккаунтов (user enumeration) | При неверном пароле и при несуществующем email выдаётся одно и то же сообщение. Для несуществующего email пароль проверяется по хешу-заглушке, чтобы время ответа было одинаковым. Регистрация на уже занятый email и восстановление пароля для несуществующего адреса выглядят так же, как обычно, а письма отправляются в фоне, чтобы не выдавать разницу во времени. Владельцу занятого адреса приходит уведомление о попытке регистрации. | `app/main.py` (`register`, `forgot`, `start_code_step`) |
| Почтовая бомбардировка (email bombing) | Повторная отправка кода не чаще раза в минуту, не больше 20 кодов с одного IP в час. | `app/otp.py` (`issue_limit_reached`) |
| CSRF | Каждая форма содержит случайный токен, который сравнивается за постоянное время. Cookie сеанса выставляются с `SameSite=Lax`. | `app/security.py`, все `POST` в `app/main.py` |
| XSS | Шаблоны Jinja2 экранируют данные автоматически. CSP `script-src 'self'` запрещает встроенные и чужие скрипты. Данные в письмах экранируются через `html.escape`. | `app/main.py` (`security_headers`), `app/mailer.py` |
| Clickjacking | `frame-ancestors 'none'` и `X-Frame-Options: DENY`. | `app/main.py` |
| Кража cookie сеанса | Cookie выставляются с флагами `HttpOnly`, `SameSite=Lax` и `Secure` при HTTPS, плюс HSTS. Сеансы хранятся на сервере: при выходе запись удаляется, поэтому украденная копия cookie перестаёт работать. Сеанс живёт не больше 7 дней и завершается после суток бездействия. | `app/sessions.py` |
| Фиксация сеанса (session fixation) | После входа старое содержимое сессии стирается и выдаётся новый токен. | `app/sessions.py` (`create_session`) |
| Захваченный аккаунт | Уведомление на почту при входе с нового устройства. Список активных сеансов, кнопки «Завершить» и «Выйти на всех других устройствах». Смена или сброс пароля завершают все остальные сеансы и отзывают доверие ко всем устройствам. | `app/main.py` (`complete_login`, `password_changed`) |
| IDOR (чужие сеансы и устройства) | Все запросы на завершение сеанса или отзыв доверия содержат условие `AND user_id = ?` текущего пользователя. | `app/sessions.py` |
| Смена email злоумышленником | Нужен текущий пароль. Код приходит на новый адрес, а старому адресу отправляется уведомление. | `app/main.py` (`change_email`) |
| Смена пароля с чужого открытого сеанса | Нужен текущий пароль и код из письма. Новый пароль начинает действовать только после ввода кода. | `app/main.py` (`change_password`) |
| SQL-инъекции | Во всех запросах используются параметры `?`, строки в SQL не склеиваются. | все модули |
| Огромные запросы (DoS) | Ограничена длина всех полей. Пароль не длиннее 128 символов, так как Argon2 тратит ресурсы пропорционально длине. | `app/main.py`, `app/config.py` |
| Кеширование личных страниц | `Cache-Control: no-store` на всех страницах, кроме статики. | `app/main.py` |
| Утечка секретов | Секреты хранятся только в `.env`, который не попадает в git. Приложение не запустится с почтой без собственного `SECRET_KEY`. Swagger и OpenAPI отключены. | `.gitignore`, `app/main.py` (`lifespan`) |

## Генератор паролей

Пароль генерируется в браузере и на сервер не уходит до отправки формы. Используется `crypto.getRandomValues`, а для равномерного распределения символов применяется rejection sampling (без смещения из-за деления по модулю). Пароль длиной 20 символов из набора в 70 символов даёт около 120 бит энтропии. В нём гарантированно есть символ каждого типа, после чего символы перемешиваются алгоритмом Фишера — Йетса. Из набора исключены похожие символы (`0/O`, `1/l/I`). Код находится в `app/static/app.js`.

## Известные ограничения

- **Email как второй фактор** (по умолчанию) слабее приложения-аутентификатора: если взломан почтовый ящик, взломан и второй фактор. Поэтому пользователю предлагается подключить приложение. Аппаратные ключи (WebAuthn / passkeys) пока не поддерживаются.
- **Смена `SECRET_KEY`** делает недействительными все подключённые приложения (секреты TOTP зашифрованы этим ключом) и все резервные коды. Ключ нужно хранить и не менять без необходимости.
- **Блокировка по email** позволяет злоумышленнику на 15 минут заблокировать вход чужому аккаунту, вводя неверные пароли. Это осознанный компромисс в пользу защиты от подбора.
- **Доверенное устройство**: если украдена cookie `device`, второй фактор на этом устройстве пропускается. Пароль при этом всё равно нужен. Доверие можно отозвать в кабинете, и оно отзывается автоматически при смене пароля.
- **Проверка по утечкам** выполняется через внешний сервис. Если HIBP недоступен, проверка пропускается (fail open), а в лог пишется предупреждение.
- **IP за прокси**: если сайт стоит за nginx или CDN, для правильного определения IP клиента нужно запускать uvicorn с `--proxy-headers --forwarded-allow-ips=<адрес прокси>`.
- **SQLite** подходит для одного сервера. Для нескольких серверов нужен PostgreSQL.
