# Как устроено шифрование

Коротко: ключи создаются на устройстве и не покидают его. Сервер хранит и пересылает только шифротекст. Обычные чаты защищены от сервера и от кражи базы. Секретные чаты дают ещё и прямую секретность: украденный сегодня ключ не раскрывает вчерашние сообщения.

Все примитивы взяты из библиотеки [`cryptography`](https://cryptography.io), ничего самописного:

| Что | Чем |
|---|---|
| Обмен ключами | X25519 |
| Подписи | Ed25519 |
| Вывод ключей | HKDF-SHA256, HMAC-SHA256 |
| Шифрование | ChaCha20-Poly1305 (AEAD) |
| Ключ хранилища из пароля | Argon2id, 64 МБ, 3 прохода |

## Ключи устройства (`e2e/keys.py`)

При первом входе клиент создаёт три пары ключей:

- `identity_dh` (X25519): долговременный ключ устройства для шифрования;
- `identity_sign` (Ed25519): подписывает prekey и сообщения обычных чатов;
- `signed_prekey` (X25519): нужен, чтобы начать секретный чат, пока собеседник не в сети. Подписан `identity_sign`.

На сервер уходят только открытые половины (`PublishKeys`). Сервер проверяет подпись prekey, а `key_id` вычисляет сам из ключей. Если `key_id` поменялся (новое устройство), друзья получают событие `KEY_CHANGED`.

Закрытые ключи лежат в `~/.les_iz_shishek/keystore/<имя>.bin`. Файл зашифрован ChaCha20-Poly1305 ключом, выведенным из пароля через Argon2id (`e2e/keystore.py`). Запись атомарная: сначала временный файл, потом замена.

## Обычные чаты (`e2e/regular.py`)

```
mk  = случайные 32 байта                         — ключ одного сообщения
ct  = ChaCha20-Poly1305(mk, текст, AD)
AD  = "regular/v1|отправитель|получатель"

для каждого читателя R (получатель и сам отправитель):
    e      = одноразовая пара X25519
    wrapR  = HKDF(DH(e, R.identity_dh), info = метка ‖ e.pub ‖ R.pub)
    header.to_R = ChaCha20-Poly1305(wrapR, mk, AD)

подпись = Ed25519(identity_sign, AD ‖ header ‖ ct)
```

- **Сервер не может прочитать сообщение**: для этого нужен закрытый `identity_dh` одного из собеседников.
- **Сервер не может подделать сообщение**: подпись проверяется открытым ключом отправителя, который клиент запомнил раньше.
- **Сервер не может переадресовать сообщение** («это письмо от Алисы для Карла»): имена входят в AD и в подпись, расшифровка не пройдёт.
- **Свои сообщения видны в истории**: ключ сообщения завёрнут и для отправителя.

Слабое место: прямой секретности нет. Тот, кто украдёт `identity_dh` и пароль от хранилища, расшифрует всю историю с сервера.

## Секретные чаты (`e2e/ratchet.py`)

Реализация спецификаций Signal: [X3DH](https://signal.org/docs/specifications/x3dh/) и [Double Ratchet](https://signal.org/docs/specifications/doubleratchet/).

### Начало чата (X3DH)

Алиса начинает чат с Бобом, который может быть не в сети:

```
проверить подпись SPK_B ключом IK_sign_B
EK_A = одноразовая пара
DH1 = DH(IK_A, SPK_B)
DH2 = DH(EK_A, IK_B)
DH3 = DH(EK_A, SPK_B)
SK  = HKDF(0xFF×32 ‖ DH1 ‖ DH2 ‖ DH3)
AD  = IK_A.pub ‖ IK_B.pub
```

Открытые `IK_A` и `EK_A` идут в заголовке первых сообщений (поле `init`), пока Боб не ответит. Боб считает тот же `SK` со своей стороны и сверяет `IK_A` с ключом Алисы, который отдаёт сервер.

### Храповик (Double Ratchet)

- **Симметричный храповик**: для каждого сообщения `mk = HMAC(ck, 0x02)`, `ck = HMAC(ck, 0x01)`. Ключ сообщения используется один раз и стирается.
- **Храповик Диффи — Хеллмана**: в каждом ответе новая пара X25519. Корневой ключ обновляется через `HKDF(root, DH(...))`.
- **Сообщения не по порядку**: ключи пропущенных сообщений запоминаются, но не больше 100 на цепочку (`MAX_SKIP`).
- **Повтор и подделка**: повторное сообщение не расшифруется, потому что его ключ уже стёрт. Если сообщение подделано, состояние откатывается и чат не ломается.
- **Шифр сообщения**: ChaCha20-Poly1305, ключ и nonce выводятся из `mk` через HKDF, AD = `AD ‖ заголовок`.

### Что ещё делает клиент (`client/core.py`)

- Сервер стирает шифротекст секретного сообщения, как только получатель подтвердил доставку (`Acknowledge`). Недоставленные сообщения живут не больше 7 дней.
- Сообщения и состояние храповика хранятся только в зашифрованном хранилище на устройстве.
- **Таймер самоуничтожения**: 10 секунд, минута, час или день после прочтения.
- **Закрыть чат**: собеседнику уходит сообщение `close`, и обе стороны стирают и переписку, и состояние храповика.
- **Если оба начали чат одновременно**, остаётся чат того, чьё имя меньше по алфавиту. Обе стороны выбирают одинаково, договариваться не нужно.
- **Если собеседник сменил устройство**, секретный чат закрывается: новое устройство не знает его ключей.

## Код безопасности

`safety_number()` в `e2e/keys.py`: для каждого собеседника 5200 раз считается SHA-512 от имени и открытых ключей. Это растягивание, как в Signal: подобрать ключ с похожим кодом становится дорого. Две половины сортируются, поэтому у обоих код одинаковый. На экране он выглядит как 60 цифр группами по 5.

Если цифры у собеседников совпали, сервер не подменил ключи. Клиент запоминает, что ключ проверен, и снимает отметку, когда ключ собеседника меняется.

## Тесты

`tests/test_crypto.py`: чтение посторонним, подделка отправителя и текста, сообщения не по порядку, повтор, прямая секретность (украденное состояние не открывает прочитанное), откат при подделке, подделанный prekey, хранилище и код безопасности.

`tests/test_grpc.py` (`test_client_*`): два клиента переписываются через настоящий сервер в обычном и секретном чате. Проверяется, что после доставки на сервере ничего не остаётся, что таймер срабатывает и что смена устройства закрывает секретный чат.
